# Checkpoint 06.5.2 reminder family inventory

Source of names: `shared/enums.ts` `REMINDER_TRIGGER_FAMILIES` and `drizzle/migrations/0002_seed.sql`. Twelve names, eleven seeded rules. `CUSTOM_FOLLOWUP` is not seeded and has no batch loader.

Call path for a rule PATCH: `PATCH /api/v1/reminder-rules/:id` in `server/http/app.ts` → `updateRule` → permission `reminders.manage_rules` → `UPDATE reminder_rule_definitions` → `loadDesiredForRule` → `syncRuleInstances` (set load, batched writes of 80, one `next_action` update). `CUSTOM_FOLLOWUP` still falls through to `SELECT DISTINCT case_id` and serial `recomputeRemindersForCase`.

Event and cron paths still call `recomputeRemindersForCase` without `onlyRuleId`: case writes, document approval, bookings, bank/courier, and `processDueReminders` (limit 100 due rows, then one full recompute per touched case). Those paths were not rewritten.

## Work that is still serial

`recomputeRemindersForCase` remains the path for approvals, ETA edits, snooze evaluation on case events, and `processDueReminders`. A cron pass that touches many cases was not timed on the 500-case store. Rule PATCH no longer uses that loop for the 11 seeded families.
